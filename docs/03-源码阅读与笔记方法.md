# 03 · 源码阅读与笔记方法

## 一、三层读法

1. **骨架**：只看类的成员数据与公开接口，画出关系图（谁持有谁、谁继承谁）。
   第一遍**故意忽略**所有宏、下划线前缀、特化分支。
2. **主干**：跟一条完整调用链走到底。例如 `list::push_back` → 分配节点 → 链接 →
   `iterator` 如何 `++`。
3. **细节**：第二遍才看 `#ifdef`、allocator 萃取、异常安全、偏特化分支。

> 顺序反了（一上来抠细节）是最常见的卡住原因。

## 二、读任何一段 STL 源码，先问这 8 个问题

1. 数据实际存在哪？（连续内存 / 节点 / 分段）
2. 谁负责分配与释放？（allocator）
3. 迭代器是什么类型？属于哪个 category？
4. `begin()` / `end()` 分别指向什么？为什么 `end()` 不能解引用？
5. 拷贝 / 移动时发生了什么？深拷贝还是浅拷贝？
6. 模板参数里哪些是「策略」（可替换的），哪些是「数据」？
7. 这个设计在拿什么换什么？（时间 / 空间 / 迭代器失效）
8. 如果让我用现代 C++ 重写，哪些可以简化？

## 三、笔记模板（`docs/` 下每篇都按这个写）

```text
## 概念
一句话定义，用自己的话，不抄 PPT。

## 为什么需要它
没有它会怎样（举一个具体出错场景）。

## 关键实现
最少量的代码 / 内存图，标出"反直觉"的那一行。

## 我的验证
在 src/ 里写了哪个例子、编译器报了什么错、我改了什么。

## 还没搞懂
诚实列出，下次回来补。
```

## 四、把「看懂」变成「写对」的调试手段

- 打印 `sizeof` 与对象地址，验证内存布局猜想。
- 在构造 / 拷贝 / 析构里打日志，数清 `c3 = c1 + c2` 到底调用了几次。
- `g++ -E` 展开宏，看模板与宏真正变成什么。
- 故意改坏一行（去掉 `const`、去掉 `&`、去掉 `virtual`），读编译器报错。

## 五、把老课件代码迁到 C++17 的常见坑

| 老写法 | 现代替代 | 报错特征 |
| --- | --- | --- |
| `auto_ptr` | `unique_ptr` | 已移除 / 弃用警告 |
| `bind2nd` / `not1` / `mem_fun` | `lambda` / `std::bind` | 找不到标识符 |
| `hash_set` / `hash_map` | `unordered_set` / `unordered_map` | `<ext/...>` 头文件不存在 |
| 手写迭代器嵌套 typedef 继承 | `std::iterator_traits` | 嵌套类型缺失 |
| `throw()` 异常规格 | `noexcept` | C++17 直接编译错误 |
| `NULL` / `0` 当空指针 | `nullptr` | 重载决议歧义 |

> 迁移本身就是最好的考试：编译器会替侯捷老师出题。
> 本仓库 `src/` 的示例刻意用 C++17 重写课件里的经典例子，就是这个用意。

## 六、资料怎么放

- 视频 / PPT / 原始课件 → `third_party/`（子模块，不改动、不提交进本仓库）。
- 自己重写的 C++17 代码 → `src/`，必须能编译、能跑、能过 CTest。
- 自己的理解 → `docs/`，只写「我自己的话」。

三者分开，才不会出现「资料存了一堆、脑子还是空的」。
