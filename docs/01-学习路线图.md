# 01 · 学习路线图：先把思路理顺

> 这一篇回答「按什么顺序学」。先有地图，再去走路；否则每一门课都像一堆散落的知识点。

## 一、一条主线

侯捷全部课程其实只围绕一条线：

```text
数据放在哪  →  谁负责生死  →  怎么抽象成类型  →  怎么复用而不重复
 (内存布局)      (构造/析构/RAII)      (class / 模板)       (继承 / 泛型 / STL)
```

- **上册（OOP 上）**：一个 `Complex` / `String` 对象怎么设计，才能既安全又高效。
- **下册（OOP 下 · 对象模型）**：编译器在背后偷偷加了什么（vptr、this、构造析构顺序、临时对象）。
- **上层建筑（STL / GP）**：把「数据结构」与「算法」拆开，用迭代器粘起来；模板在编译期做类型计算。
- **地基（内存管理 / Startup）**：`new` 到底做了什么，程序在 `main` 之前 / 之后发生了什么。

**如果只记一句话**：先搞清楚「一个对象在内存里长什么样」，后面所有课都是在这张图上加东西。

## 二、课程地图与先修关系

| 顺序 | 课程 | 解决什么问题 | 先修 |
| --- | --- | --- | --- |
| 1 | C++ 面向对象高级编程（上） | 类的设计：头文件、构造函数、参数传递与返回值、操作符重载、三大函数、堆与栈 | C 基础、指针 |
| 2 | C++ 面向对象高级编程（下）· 对象模型 | 模板、转换函数、pointer-like / function-like、vptr 与 vtbl、this、动态绑定、const、new/delete | 1 |
| 3 | STL 标准库与泛型编程 | 容器、分配器、迭代器、算法、仿函数、适配器、traits；OOP vs GP | 1 + 2（尤其模板） |
| 4 | C++11/14 新标准 | 移动语义、auto、lambda、变长模板、type traits | 3 |
| 5 | 内存管理机制 | `operator new/delete` 重载、内存池、allocator、malloc 的 cookie 与对齐 | 1 + 3 |
| 6 | C++ Startup（程序的生前死后） | 启动代码、全局对象、堆栈布局、CRT | 5 |
| 7 | 设计模式 | 用 C++ 落地常见模式 | 1~5 |

## 三、推荐顺序与理由

1. **先 1 后 2，不要合并看**：上册把「类写对」，下册把「编译器为什么这么干」讲透；跳过去直接看 vptr 会没有落点。
2. **STL 放在对象模型之后**：STL 的难点不在容器 API，而在模板与 traits；没有第 2 门的模板基础，第一页 `typedef` 就劝退。
3. **内存管理放后面**：它默认你已理解构造 / 析构和 allocator，提前看只会背下一堆 API。
4. **C++11/14 放在 STL 之后**：`move`、`type traits` 是对 STL 设计的一次「现代化重述」，先见过老写法才能体会它解决了什么。

## 四、常见的三条错误路线

- 直接刷 STL 源码：没有对象模型和模板基础，读到的全是噪音。
- 只看视频不敲代码：视频是单向的，「看懂」是一种错觉（见 [02](02-为什么侯捷难.md)）。
- 按资料目录从上往下学：资料是按**课程**归类的，不是按**依赖**归类的，必须按上表重排。

## 五、每一阶段的验收标准

| 阶段 | 能写出 / 讲清楚 |
| --- | --- |
| 1 | 自己实现 `Complex`、`String`（含 Big Three）并解释深拷贝 |
| 2 | 画出含虚函数对象的内存布局，解释动态绑定的调用链 |
| 3 | 手写一个简化 `iterator_traits`，解释 `distance` 如何按迭代器类别分派 |
| 4 | 解释移动语义为什么能省掉一次拷贝 |
| 5 | 重载 `operator new/delete` 实现一个最小内存池 |
| 6 | 说出 `main` 之前全局变量是怎么被构造的 |

> 验收标准对应 `src/` 里的示例：每个例子既能编译运行，也正好覆盖上面某一行。
