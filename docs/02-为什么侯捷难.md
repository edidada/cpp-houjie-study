# 02 · 为什么说侯捷的 C++ 课程比较难？

> 这是本仓库的**重点**篇。先给结论：**难的不是 C++ 语法，而是提问的层次。**
> 大多数教程问「怎么用」，侯捷全程问「为什么必须是这样」。
> 前者训练使用者，后者同时要求你当实现者和设计者。

## 一、范式层：从「调 API」切换到「拆机制」

### 1.1 起点是对象模型，不是语法

普通 C++ 教程的第一章是 `class` 怎么写、`vector.push_back` 怎么调。
侯捷的第一章是：头文件为什么用防卫式声明、构造函数为什么用初始化列表、
`operator+=` 为什么返回引用而 `operator+` 必须按值返回、临时对象什么时候析构。

一个看似简单的 `complex c3 = c1 + c2;`，他要你数清楚：几次构造、几次拷贝、
临时对象活到哪一行、`return by value` 为什么不能用引用。这要求你先建立
「程序 = 数据 + 数据在内存中的布局 + 控制流」的心智模型，而不是「API 调用清单」。

### 1.2 两套范式并行：OOP 与 GP

STL 部分明确讲 **OOP vs GP**：容器与算法分离、通过迭代器粘合。这跟大多数人熟悉的
「继承 + 虚函数」（运行时多态）完全是两套思维。模板、全特化、偏特化、模板模板参数、
成员模板、traits 是**编译期**的类型计算。只有一套范式的人，会在这里第一次感到
「代码认识我，我不认识代码」。

## 二、抽象层：读源码，而不是读文档

### 2.1 读的是工业级实现，满眼都是「非教学细节」

`list` 是环状双向链表加一个尾部空节点、`vector` 是三个指针、`deque` 是分段连续加
中控 map、`RB-tree` 与 `hashtable` 的质数表与桶、`iterator_traits` 的五种
category 与 `distance` / `advance` 的编译期分派……源码里塞满 `typedef`、宏、
下划线前缀、偏特化分支、异常安全处理。第一遍读，像在读另一门语言。

### 2.2 他追问的是「为什么这么设计」，这类问题没有标准答案

- 为什么 `deque` 不做成真连续？
- 为什么 `list::end()` 要留一个空节点而不是 `nullptr`？
- 为什么 allocator 要从容器里独立出来？
- 为什么 `vector` 扩容通常是两倍？
- 为什么需要 `iterator_traits`，直接问迭代器不好吗？

视频给的是结论，**取舍的推演过程要你自己补**。这比记住一个 API 的签名难一个量级，
因为它没有可以背的答案，只能靠你重建当时的约束条件。

## 三、知识结构层：网状依赖，缺一环就卡住

一门课同时牵扯：C 的指针与 `malloc`、数据结构（红黑树、哈希表）、
操作系统（堆栈、内存管理）、编译链接（符号、对齐、cookie）、一点汇编（vtable 布局）。

线性课程可以跳章节，网状知识不行——**任何一环缺了，后面整段会突然听不懂**，
而且你很难定位到底是哪一环缺的，因为报错信息不会告诉你「你缺的是内存对齐」。

再加一重负担：中文讲授 + 英文源码 + 标准术语（specialization、traits、allocator、
iterator category、dynamic binding）三种表述要来回对齐，笔记稍不留神就记成三套东西。

## 四、实践层：没有反馈闭环，且存在时代差

### 4.1 单向视频，「看懂」是错觉

没有练习、没有评测、没有人改你的代码。于是最容易的状态是「自以为懂了」：
看 `String` 的三大函数觉得理所当然，直到自己写一遍才发现忘了自赋值检查、忘了深拷贝。
**只有当你真的实现一个 `vector`，或试图给别人讲清多重继承下 vptr 的偏移时，
理解漏洞才会暴露。**

### 4.2 课件代码有时代差

课件来自 VC6 / SGI STL / GCC 2.9 的时代：`auto_ptr`、`bind2nd`、`hash_set`、
`<ext/...>`、`__STL` 宏、`throw()` 异常规格、老式仿函数适配器。用 C++17 直接编译
会报错；讲义、PPT、代码三者还是分离的，跟着敲一遍成本很高。你得先做一遍「移植」，
才谈得上「学习」。

### 4.3 信息密度高、跨度大

从 `Complex` 到对象模型，到 STL 源码，到内存管理，到「程序的生前死后」，中间没有
「例题—反馈—巩固」的缓冲带。一节课里出现的新概念，往往比普通教程一章还多。

## 五、一句话：它同时要求三个身份

| 身份 | 要求 | 普通课程训练到哪 |
| --- | --- | --- |
| 使用者 | 会调用、会写业务代码 | ✅ |
| 实现者 | 能自己把 `String` / `vector` / 内存池写出来 | ❌ |
| 设计者 | 能解释「为什么这样设计、换掉要付什么代价」 | ❌ |

侯捷的课默认你三个都要有。**难的从来不是 C++，是你被要求换一种思考方式。**

## 六、怎么破

1. **先画内存图**：`sizeof`、对象地址、构造析构顺序，全部打印出来验证猜想。
2. **每个例子亲手敲 → 编译 → 单步 → 故意改坏**：去掉一个 `const`、一个 `&`、
   一个 `virtual`，读编译器报错。报错比视频诚实（这就是 `src/` 存在的意义）。
3. **顺序固定，不要跳**：按 [01](01-学习路线图.md) 的表走，缺哪环补哪环。
4. **读源码先画骨架**：第一遍只画类关系图与一条调用链，忽略所有宏和下划线细节。
5. **用自己的话写笔记**，不复制 PPT；写不出来就是没懂（这就是 `docs/` 存在的意义）。
6. **用 C++17 重写课件代码**：让编译器当老师，迁移过程本身就是考试。
7. **验收标准改成「能讲清楚」**：讲给不懂的人听，卡住的地方就是没懂的地方。

## 七、自检清单

能不假思索地回答下面十条，才算真的过了第一遍：

- [ ] `complex c3 = c1 + c2;` 一共发生几次构造 / 拷贝 / 析构？临时对象活到哪？
- [ ] 三大函数（拷贝构造、拷贝赋值、析构）为什么必须一起出现？
- [ ] 含虚函数的对象内存布局长什么样？`sizeof` 为什么会变大？
- [ ] `vector` 的三个指针分别指向什么？
- [ ] `iterator_traits` 解决了什么问题？没有它 `distance` 要怎么写？
- [ ] `new` 表达式被拆成哪三步？`delete` 呢？
- [ ] `deque` 为什么不是真连续？它的迭代器为什么要带中控指针？
- [ ] `list::end()` 为什么不是 `nullptr`？
- [ ] 模板全特化与偏特化的区别是什么？偏特化能作用在函数模板上吗？
- [ ] 深拷贝与浅拷贝分别在什么时机炸掉？

> 答不上来的条目，去 `src/` 找对应示例改一遍，再把答案补进自己的笔记。
