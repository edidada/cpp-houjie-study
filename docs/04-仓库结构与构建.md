## 二、`third_party` 三个子模块

| 目录 | 来源（edidada 下的 fork） | 上游 | 内容 | 默认分支 |
| --- | --- | --- | --- | --- |
| `bilibili-plus` | `edidada/Bilibili-plus` | `ZachL1/Bilibili-plus` | 侯捷全系列视频、PPT、源代码 | `master` |
| `houjie-course` | `edidada/houjie-course` | `TaoLu52/-C-HouJie` | 侯捷 C++ 系列课程资料 | `master` |
| `houjie-notes` | `edidada/HoujieCppNotes` | `smzztx/HoujieCppNotes` | 纯 Markdown 学习笔记 | `main` |

**一个 GitHub 限制**：`TaoLu52/-C-HouJie` 本身是 `ZachL1/Bilibili-plus` 的 fork，
两者属于**同一个 fork 网络**；GitHub 不允许一个账号在同一网络里拥有两个同名 fork，
所以 `gh repo fork` 会直接复用已有的 `edidada/Bilibili-plus`。这里用
`gh repo fork --fork-name houjie-course` 改名另建了一个独立仓库以保留该路径，
其 `parent` 会显示为网络根 `ZachL1/Bilibili-plus`。上游原始链接仍记录在根 README。

`houjie-course` 特意锁定在 `2d231c8`（即 `TaoLu52/-C-HouJie` 的快照）而非 fork 的
默认 HEAD：同一 fork 网络内的对象共享，按 SHA 拉取可用，这样两个子模块内容不重复。

**关于体积**：前两个仓库各约 268MB（大量视频与 PPT），第三个约 77MB。因此：

- 子模块以 **gitlink** 形式登记（`.gitmodules` + 锁定的提交），**不预先 checkout**。
  `git submodule status` 前面的 `-` 表示「未初始化」，这是正常状态，不是错误；
- `.gitmodules` 中 `shallow = true`，后续拉取自动是浅克隆；
- **CI 不 checkout 子模块** —— 编译只依赖 `src/`，拉几百 MB 视频没有意义；
- 需要资料时再执行 `git submodule update --init --depth 1`。

## 三、CMake 结构

- 顶层 `CMakeLists.txt`：`C++17`、`-Wall -Wextra`（不开 `-Werror`）、
  `enable_testing()`、`add_subdirectory(src)`。
- `src/CMakeLists.txt`：每个示例一个 `add_executable` + `add_test`，
  目录名即课程阶段编号，方便对照 [01](01-学习路线图.md)。

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

| 示例 | 对应课程阶段 | 考察点 |
| --- | --- | --- |
| `01_complex` | OOP（上） | 初始化列表、`+=` 返回引用、`+` 按值返回临时对象 |
| `02_string` | OOP（上） | Big Three、深拷贝、自赋值 |
| `03_object_model` | OOP（下） | 虚函数、动态绑定、vptr 与 `sizeof` |
| `04_gp_traits` | STL / GP | 类模板、偏特化、`iterator_traits` 式萃取 |
| `05_memory` | 内存管理 | `new` 三步、`operator new/delete` 重载、placement new |

## 四、CI

`.github/workflows/cmake.yml` 在 `push` / `pull_request` / 手动触发时运行：

```text
actions/checkout@v4（不拉子模块）
  → cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
  → cmake --build build
  → ctest --output-on-failure
```

查看结果：

```bash
gh run list --limit 5
gh run watch
gh run view <run-id> --log
```

## 五、常用命令速查

```bash
git submodule status                     # 看三个子模块锁定在哪个提交
git submodule update --init --depth 1    # 首次拉取资料
git submodule update --remote --depth 1  # 更新到 fork 最新提交
gh repo view --web                       # 打开私有仓库
gh run list                              # 看 Actions 结果
```
